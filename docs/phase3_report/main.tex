\vspace{0.70cm}
\sectiontitle{Project Abstract (2 pts)}
\vspace{0.05cm}
\instruction{(Brief restatement of your project's main goal. Max 300 words).}
\vspace{0.12cm}
\answerbox{3.60cm}{%
Our project shows how a banking application handles simultaneous requests without leaving incorrect balances. Customers use a Flask website to deposit, withdraw and transfer sample money. Account locks coordinate threads, while SQLite transactions keep each payment complete or roll it back. Phase III builds on the working Phase-II prototype with repeated concurrency measurements and verification of the trained BankSim model. The administrator can inspect transaction history, execution traces and risk alerts. Model training and the recorded BankSim test evaluation are complete; validation for live INR transactions remains unfinished.}

\vspace{0.70cm}
\sectiontitle{Updated Project Approach and Architecture (2 pts)}
\vspace{0.05cm}
\instruction{(Describe your current approach, including system design,
communication protocols, libraries used, etc.\\ Max 300 words).}
\vspace{0.25cm}
\answerbox{4.75cm}{%
Flask serves the browser over local HTTP. Web routes check login, role, account ownership and form tokens before calling the Python transaction service. The service locks account IDs in ascending order and starts \texttt{BEGIN IMMEDIATE} before reading balances. Debit, credit and the successful ledger entry commit together. Failures roll back, with a separate attempt record written afterward. SQLite stores amounts in integer paise and uses WAL mode. Python threads drive the simulator and Concurrency Lab. Rule checks run after payment commit; optional Groq review uses an external HTTPS API. The BankSim logistic-regression model was trained using scikit-learn and remains an offline experiment. Its saved parameters were checked against the original later-day test data. SQLite still permits only one writer at a time.}

\sectiontitle{Challenges/Roadblocks (7 pts)}
\vspace{0.05cm}
\instruction{(Describe the challenges that you have faced or are facing so
far and how you plan to solve them. Max 300 words).}
\vspace{0.18cm}
\answerbox{4.05cm}{%
A good BankSim score does not establish performance on our INR transfers. At the stored threshold, the model missed 640 of 1,320 labelled fraud cases, so further calibration needs suitable labelled examples. More threads also gave uneven timings because account contention and SQLite's single writer limit overlap. We plan longer runs with more accounts and several workload seeds. External review may fail after a payment commits; local rules remain available. Abrupt process failure, power loss and reliable delivery of every review record still need dedicated testing.}

\vspace{0.05cm}
\instruction{(Describe what are the key outcomes / deliverables of the
project. Max 200 words).}
\vspace{0.35cm}
\answerbox{3.35cm}{%
For the demonstration, a customer can send money between sample accounts and open the resulting receipt. The administrator can then inspect the recorded steps and any alert raised for that payment. A separate lab lets us demonstrate a lost update or an interrupted transfer without changing these customer balances. Alongside the application, the submission includes saved BankSim model parameters, workload results and a seven-page research draft. These files provide evidence to discuss during the presentation. The slides still need a final review, and the demonstration video has not been completed.}

\vspace{0.75cm}
\sectiontitle{Progress Overview (2 pts)}
\vspace{0.05cm}
\instruction{(Summarize how much of the project is done, what's behind
schedule, what's ahead of schedule. Max 200 words.)}
\vspace{0.25cm}
\answerbox{4.45cm}{%
The Phase-II report left us with two main follow-ups: check the model more carefully and repeat the concurrency measurements. The 2 November test record now covers 45 passing tests. For the workload check, each run began with three fresh accounts; 100 requests were repeated across eight thread/workload combinations, giving 24 runs and 2,400 successful operations. Every run reconciled its closing balance. Checking the saved classifier again gave the recorded BankSim scores, although this reused the same test data. Web and trace files have since been committed locally. The remaining work concerns INR calibration, crash testing and the final presentation material. We have not assigned a completion percentage because these checks are still open.}
